# Context Check 通用审查协议

> `check/*/AGENTS.md` 的所有检查均遵循本协议。检查默认只读；只有用户明确要求修复时才修改文件。

## 审查原则

1. **先清点再比较**：先确认实际文件、Manifest 和索引，再进行内容审查。
2. **双向追溯**：既检查来源要求是否被覆盖，也检查生成资产是否存在无来源依据的内容。
3. **权威边界**：业务事实以 PRD/领域源文档为准；技术事实以架构源文档为准；工程强制约束以 `.context/criterion.md` 为准；`openspec/config.yaml` 仅是派生快照。
4. **证据优先**：每条发现必须引用文件路径和章节、字段或行号。无法确认时标记为 `[AMBIGUOUS]`，不得推断为事实。
5. **按需加载**：只读取当前画像需要的文件。`source/` 默认不读取，只有源资产对照画像才读取。
6. **报告与修复分离**：一次检查只生成报告。用户明确要求 `--fix` 或确认具体发现后，才执行修改并更新 Manifest。

## 差异标签

| 标签 | 含义 |
|------|------|
| `[MISSING]` | 权威来源存在要求，但目标资产未覆盖 |
| `[CONFLICT]` | 两处对同一事实或约束的定义互相矛盾 |
| `[DEVIATION]` | 命名、数值、路径或语义无依据偏离 |
| `[UNJUSTIFIED]` | 目标资产出现来源无法追溯的设计或约束 |
| `[DESYNC]` | Manifest、README、索引与文件系统不同步 |
| `[STALE]` | 状态、时间、版本或说明已经过期 |
| `[AMBIGUOUS]` | 证据不足，需要人工裁决 |

## 严重程度

| 级别 | 判断标准 |
|------|----------|
| `P0` | 影响业务正确性、安全、数据完整性，或阻断工具解析/实施 |
| `P1` | 影响跨文档、契约、实现或规划一致性 |
| `P2` | 影响索引、可追溯性、维护性或文档可读性 |

## 标准输出

1. 审查范围、权威来源、排除项
2. 总体结论：`PASS` / `PASS (Conditional)` / `FAIL`
3. 覆盖或同步矩阵
4. 按 `P0 → P1 → P2` 排序的差异清单
5. 无法裁决事项
6. 最小修复建议

每条差异必须包含：`标签`、`严重度`、双方证据、影响、应修改哪一方及原因。不要用无法复现的百分比评分。
